# Purpose

## Goal

Define the realistic current position and next strategic direction for ONOKO as a character IP across the active local projects.

## Core Question

Given the current assets, apps, tools, and release readiness, what should ONOKO become first so that the project can realistically earn attention, validate demand, and later monetize without overbuilding?

## Recommended Answer

ONOKO should be positioned first as a small, consistent, tool-linked character IP:

```text
ONOKO is a playful cyber-oracle character who helps users observe themselves, interpret signals, and turn creative noise into small next actions.
```

The immediate public product should not be a large game, full story universe, or AI platform. It should be a compact public loop:

```text
SNS character presence -> ONOKO ARCANA low-cost app -> feedback/analytics -> stronger character assets -> later story/game/products
```

## Why This Is Realistic

- ONOKO Command Center already supports character operations, posting, asset QA, LoRA candidate selection, prompt blocks, publishing prep, and analytics.
- ONOKO ARCANA is closest to an external product because it has a local package, smoke tests, release notes, and a concrete user workflow.
- ONOKO ORACLE is conceptually strong but more complex and harder to explain or trust as a first paid product.
- Yoitomoshi Art Generator is valuable infrastructure but should remain mostly behind the scenes for now.
- The LoRA and image pipeline can support consistent visuals, but public model release still has license/IP/safety review blockers.
