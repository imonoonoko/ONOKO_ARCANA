# Alternatives

## Option A: ARCANA-First IP Validation

Release ONOKO ARCANA as the first public-facing artifact and use it to validate whether people respond to ONOKO's cyber-divination positioning.

Pros:

- Closest to release-ready.
- Clear user value: tarot study, local history, reflection.
- Low operational burden if distributed as an unsigned local package with clear warnings.
- Converts ONOKO from "images and plans" into something users can open.

Cons:

- Small market if presented as only a tarot tool.
- Needs packaging, screenshots, store copy, support policy, and public-facing polish.

Recommendation: choose this as the first external validation path.

## Option B: SNS-First Character Growth

Use ONOKO Command Center to run a 30-day manual posting loop before selling anything.

Pros:

- Tests character appeal without payment friction.
- Builds visual identity, voice, and analytics data.
- Reduces risk of launching to no audience.

Cons:

- Can become endless preparation if no product deadline exists.
- Social growth may be slow and noisy.

Recommendation: run this in parallel with ARCANA, but with a hard 30-day limit and simple metrics.

## Option C: ORACLE-First Experimental Product

Promote ONOKO ORACLE as the main public product.

Pros:

- More distinctive and technically impressive.
- Strong cyber-oracle identity.

Cons:

- Harder to explain.
- Public-signal forecasting and oracle text require careful disclaimers.
- Trust and usefulness are harder to validate.

Recommendation: keep as a signature lab/teaser, not the first commercial product.

## Option D: LoRA/Model-First Release

Release ONOKO LoRA publicly as the main IP asset.

Pros:

- Could attract AI-art users.
- Strong asset reuse and image generation value.

Cons:

- Current private notice explicitly requires base model license, IP policy, safety, platform rules, and public license review.
- Public model release risks losing control of character identity.

Recommendation: do not make public first. Keep private and use it to produce controlled assets.

## Option E: Full Game/Novel-First

Build a larger story product before public release.

Pros:

- Strongest long-term IP form if finished.

Cons:

- Highest scope and longest feedback loop.
- Current visible projects are better suited to tooling, oracle, and small app validation.

Recommendation: defer until ARCANA/SNS validates the character premise.
