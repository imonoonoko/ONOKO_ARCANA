# Requirements

## Strategic Requirements

1. ONOKO must have one public sentence.

   Recommended:

   ```text
   ONOKO is a playful cyber-oracle character who helps you observe signals, ask better questions, and turn uncertainty into small next actions.
   ```

2. ONOKO ARCANA should be the first paid-or-donation product candidate.

   Acceptance criteria:

   - Release page explains it as a local-first tarot study/reflection app.
   - It is clearly connected to ONOKO's cyber-oracle identity.
   - It avoids claiming guaranteed fortune-telling accuracy.
   - It has screenshots, short usage copy, known limitations, and support notes.

3. ONOKO Command Center should remain the internal IP operations cockpit.

   Acceptance criteria:

   - Use it for asset selection, post planning, caption consistency, manual publishing prep, and analytics.
   - Do not expose it as a public product before the ONOKO public loop is validated.

4. ONOKO ORACLE should be positioned as a lab-grade signature experience, not the first commercial product.

   Acceptance criteria:

   - Use it for teaser clips, world-noise snapshots, and high-concept identity.
   - Avoid hard forecasting claims in public copy.
   - Keep "observe / wait / act / ask / stop / record / compare / release / snap" as ONOKO's philosophical action vocabulary.

5. Yoitomoshi Art Generator should remain production infrastructure.

   Acceptance criteria:

   - Use it to produce consistent ONOKO assets, prompt libraries, and image variants.
   - Do not make it part of the ONOKO customer-facing promise.

6. ONOKO LoRA/model files should remain private until licensing and safety are reviewed.

   Acceptance criteria:

   - Public release is blocked until base model terms, sample safety, character/IP policy, and model card language are settled.
   - Use the model internally to create controlled public visuals.

## Product Requirements For First Public Loop

1. Publish one clear ONOKO landing surface.

   Minimum content:

   - ONOKO one-sentence definition.
   - ARCANA download/purchase link.
   - 4-6 screenshots.
   - Safety/entertainment disclaimer.
   - Link to SNS.

2. Run a 30-day manual posting experiment.

   Minimum fields:

   - Date
   - Platform
   - Series
   - Image
   - Caption
   - Impressions
   - Likes
   - Comments
   - Saves/shares where available
   - Follower delta
   - Qualitative note

3. Release ONOKO ARCANA v0.1.0 only after CI passes on the final release commit.

   Minimum gates:

   - Commit current release candidate intentionally.
   - Push.
   - Confirm CI green.
   - Tag.
   - Publish GitHub Release or external store page.

4. Use pricing as validation, not income maximization.

   Starting options:

   - Free with donation.
   - Low-price early access.
   - Paid supporter's edition after public interest is observed.

## Non-Goals

- Do not build a large metaverse/universe before public validation.
- Do not automate social posting before manual posting proves useful.
- Do not sell public LoRA rights before IP boundaries are decided.
- Do not make medical, legal, financial, or guaranteed prediction claims.
- Do not call the unsigned Electron folder package a polished installer.

## Success Metrics

30-day minimum:

- 20-30 manual posts completed.
- At least 3 post formats tested.
- At least 1 downloadable ARCANA release page published.
- At least 10 external downloads or wishlists.
- At least 3 pieces of qualitative feedback.

60-day stronger signal:

- Repeat users or comments mentioning ONOKO by name.
- One content format clearly outperforming others.
- Evidence that ARCANA is understood as an ONOKO product, not a generic tarot app.
- Clear decision to continue, pivot, or pause.
