# Orchestration: ONOKO ARCANA multi tab interface

## Execution Rules

- Keep the original objective intact.
- Ask for approval before risky, expensive, external, or destructive actions.
- Keep immediate blocking work local.
- Delegate only bounded, disjoint, materially useful packets.
- Integrate packet results before final verification.
- Treat this as a local Web/Electron UI slice; do not invoke finance/sales/game/pitch-deck domain work unless the product scope changes.
- Preserve all current storage schemas and generated card assets.

## Branching Rules
- Work in the current working tree. Do not reset or revert pre-existing edits.
- Keep implementation, tests, and docs tied to the same tab contract.

## Packet Prompts
- Requirements packet: define the minimum tab IA, acceptance criteria, KPI guardrails, and non-goals.
- UI packet: implement accessible inspector tabs with a stable right-panel height model.
- Test packet: update smoke/visual/static checks so hidden panels are opened before interaction.
- Report packet: capture evidence and repeat the Goal-completion audit before marking complete.

## Completion Audit
- Does the app visibly expose multiple inspector tabs?
- Can a user complete card reading, guide reveal, study sheet, recall practice, history filter, import/export, and clear flows after the tab change?
- Do screenshots show no overlap, clipping, or unreadable tab labels across desktop/mobile?
- Are docs and Kanban updated with exact evidence paths?
